# Changelog

Все заметные изменения в проекте документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [4.3.2] - 2026-11-13

### Added
- Опция «Включая USB-диски (HDD/SSD)»: внешние диски на USB, которые Windows
  определяет как `DRIVE_FIXED`, теперь можно резервировать. Тип шины
  определяется через `IOCTL_STORAGE_QUERY_PROPERTY` (BusType = USB).
- При смене глобальной папки хранения приложение предлагает перенести
  существующие копии в новую папку (или оставить их на месте).
- Деинсталлятор получает из реестра список ВСЕХ баз хранения
  (`BackupRootCount`/`BackupRootN`) и показывает полные пути копий.

### Fixed
- Сравнение версий при обновлении: `4.3.1` и `4.3.1.0` больше не считаются
  разными, ложное «у вас более новая версия» устранено.
- Диалог прогресса загрузки обновления действительно отображается и позволяет
  отменить загрузку; при скрытом окне обновление сообщается balloon-ом.
- Авто-проверка обновлений выполняется и при старте с `-hidden`; метка
  «последняя проверка» пишется только после успешного ответа.
- Бэкап на самой флешке (или на её томе) блокируется: раньше это приводило
  к рекурсивному копированию и заполнению носителя.
- Персональные пути профилей и имена папок проверяются при загрузке настроек;
  небезопасные значения сбрасываются/перегенерируются.
- «Удалить бэкап выбранной» работает и для профилей с персональной папкой;
  удаление не проходит сквозь junction/symlink.
- Live-watch учитывает персональную настройку `LiveWatchOverride`, а его копии
  отменяются и учитываются при безопасном извлечении.
- Устранены гонки `.tmp` при параллельных копиях, утечки сессий при повторном
  подключении и `ObjectDisposedException` из-за преждевременного `Dispose` CTS.
- Кэш индекса приёмника проверяет mtime всех каталогов, а не только корня.
- Сброс настроек профиля выбирает правильный размер буфера в списке.
- Атомарная запись `settings.json`, кэша индекса и скачанного установщика
  (`File.Move(..., overwrite: true)`).

### Changed
- SHA-256 обязателен для автообновления: без хеша установка не предлагается.
- Уведомление о подключении флешки учитывает, включено ли резервирование.
- `UsbFileWatcher` использует `DebounceMs` (1200 мс) вместо захардкоженного таймера.
- После тихого обновления приложение перезапускается скрыто, если работало скрыто.

## [4.3.1] - 2026-11-12

Патч-релиз: только производительность и накладные расходы. Функциональность и
формат `settings.json` не меняются.

### Changed
- Polling-подпись состояния флешки считается на 64-битном FNV-1a без `StringBuilder`
  и SHA-256 — ~6× быстрее (0,8 мс вместо 5,1 мс на бэкапе из 47 тыс. файлов).
- Лог пишется одним открытым `StreamWriter` вместо `AppendAllText` на каждую строку
  (~100× быстрее записи), ротация считается по фактически записанным байтам.
  Файл лога можно читать, пока приложение работает.
- Удаления при зеркалировании пишутся одной сводной строкой `[MIRROR]` вместо
  строки на каждый удалённый файл.
- `RefreshList` больше не обращается к диску на UI-потоке: результат проверки
  «есть ли сохранение» кэшируется (`Core/BackupPresenceCache.cs`, TTL 2 с,
  явная инвалидация после синхронизации, удаления и смены папки хранения).
  Сессии берутся одним снапшотом на вызов, строка ищется по словарю.
- `DefaultFlushAfterFile` по умолчанию выключен: fsync после каждого файла на
  USB-флешках стоит десятки миллисекунд на файл. Копия остаётся атомарной
  (`.tmp` → `Move`); включить можно в настройках для максимальной устойчивости
  к извлечению флешки.
- Копирование: буфер ограничивается размером файла, каталог создаётся один раз,
  убраны лишние `Flush`, `SetCreationTimeUtc` и повторный `SetLastWriteTimeUtc`
  на пути `File.Copy`.
- Прогресс очистки зеркала отчитывается батчами (128 файлов / 150 мс) вместо
  отчёта на каждый файл.
- Авто-тест новой флешки выполняется в фоне после первой синхронизации.

### Removed
- Неиспользуемое поле `FileMeta.CreationUtc`.

### Fixed
- Ложные срабатывания polling-подписи сразу после создания вложенных папок:
  NTFS обновляет время каталога лениво, поэтому вместо mtime каталогов
  учитываются имена подпапок второго уровня.

## [4.3.0] - 2026-11-05

### Added
- Ленивое создание `FileSystemWatcher`: watcher открывается только на время активной синхронизации и закрывается по завершении.
- Polling в простое с настраиваемым интервалом (`PollingIntervalSeconds`, default 30 с, min 5 с) — отслеживает изменения в корне и папках первого уровня без постоянных дескрипторов на флешке.
- Настройки `UsePollingInIdle` (default `true`), `HandleSafeRemoval` (default `true`), `ForceLegacyWatcher` (default `false`, только для отладки).
- Диагностика «Устройство занято»: подсказка про Resource Monitor / `handle.exe` в README.

### Changed
- **Поведение safe-remove:** приложение больше не удерживает `ReadDirectoryChangesW`-хэндл на флешке в простое. «Безопасное извлечение» в Windows теперь проходит без «Устройство занято» в типичном сценарии «вставил — извлёк».
- `RunDriveSettingsTest` принимает session-scoped `CancellationToken`, отменяемый при `BeginDetachForSafeRemoval`.
- `ConnectedSession.Dispose` идемпотентен.
- `ConnectedSession.FileWatcher` может быть `null` (watcher создаётся лениво).

### Fixed
- Обработка `DBT_DEVICEQUERYREMOVE` / `DBT_DEVICEQUERYREMOVEFAILED` / `DBT_DEVICEQUERYREMOVEPENDING` (Variant 1, страховка для сценария активной синхронизации).
- `BROADCAST_QUERY_DENY` при таймауте закрытия хэндлов (2000 мс).

### Removed
- Постоянный `FileSystemWatcher` в конструкторе `ConnectedSession`.
